# 🔧 Flarum 翻译显示问题修复指南

## 问题描述

切换到中文后,部分文字显示为翻译键名而不是中文,例如:
- `core.lib.search.title`
- `core.lib.search.placeholder`
- `core.lib.search_source.discussions.heading`
- `core.lib.gambits.discussions.author.key`
- `flarum-subscriptions.forum.index.following_link`
- `flarum-tags.lib.gambits.discussions.tag.hint`

## 问题原因

这通常由以下原因导致:
1. ❌ **缓存未清除** - Flarum 仍在使用旧的缓存翻译
2. ❌ **资源文件未发布** - 新的翻译文件未编译到前端
3. ❌ **浏览器缓存** - 浏览器缓存了旧的 JavaScript 资源
4. ❌ **语言包未正确加载** - Composer 依赖未安装或语言包未启用

##  解决方案

### 方案 1: 清除所有缓存(推荐)

#### 在 Heroku 上执行:

```bash
# 方式1: 通过 Heroku CLI (推荐)
heroku run bash
cd /app
php flarum cache:clear
php flarum assets:publish
exit

# 方式2: 一次性命令
heroku run "php flarum cache:clear && php flarum assets:publish"

# 方式3: 重启应用(最简单但最慢)
heroku restart
```

#### 在本地开发环境执行:

```bash
# 清除 Flarum 缓存
php flarum cache:clear

# 重新发布资源文件
php flarum assets:publish

# 清除特定缓存目录
rm -rf storage/cache/*
rm -rf storage/less/*
rm -rf storage/locale/*
rm -rf storage/views/*
```

### 方案 2: 验证语言包安装

```bash
# 在 Heroku 上检查
heroku run "php flarum info"

# 在本地检查
php flarum info

# 输出应该包含:
# Extensions Enabled:
#   - local-lang-chinese-simplified
```

如果语言包未启用,需要:
1. 访问管理后台 `/admin`
2. 点击 **扩展** 菜单
3. 找到 **简体中文** 语言包
4. 点击 **启用** 按钮

### 方案 3: 强制重新安装依赖

```bash
# 在 Heroku 上
heroku run "composer install --no-dev --optimize-autoloader && php flarum cache:clear && php flarum assets:publish"

# 在本地
composer install --no-dev --optimize-autoloader
php flarum cache:clear
php flarum assets:publish
```

### 方案 4: 清除浏览器缓存

完成服务端缓存清除后,在浏览器中:

1. **硬刷新页面**:
   - Windows/Linux: `Ctrl + F5` 或 `Ctrl + Shift + R`
   - Mac: `Cmd + Shift + R`

2. **清除浏览器缓存**:
   - Chrome: `Ctrl/Cmd + Shift + Delete` → 选择"缓存的图片和文件"
   - Firefox: `Ctrl/Cmd + Shift + Delete` → 选择"缓存"

3. **使用隐私/无痕模式测试**:
   - Chrome: `Ctrl/Cmd + Shift + N`
   - Firefox: `Ctrl/Cmd + Shift + P`

### 方案 5: 验证翻译文件完整性

检查关键翻译文件是否存在且格式正确:

```bash
# 在 Heroku 上
heroku run "ls -la packages/lang-chinese-simplified/locale/"

# 应该看到以下文件:
# core.yml
# flarum-emoji.yml
# flarum-markdown.yml
# flarum-subscriptions.yml
# flarum-tags.yml
# ... 等其他文件
```

验证 YAML 文件格式:

```bash
# 在线工具验证 YAML: https://www.yamllint.com/
# 或使用命令行工具
php -r "yaml_parse_file('packages/lang-chinese-simplified/locale/core.yml');"
```

## 🚀 完整修复流程(推荐)

按照以下顺序执行,直到问题解决:

### 步骤 1: 清除 Heroku 应用缓存

```bash
heroku run "php flarum cache:clear && php flarum assets:publish"
```

等待命令完成,查看输出是否有错误。

### 步骤 2: 重启 Heroku 应用

```bash
heroku restart
```

等待 30 秒让应用完全重启。

### 步骤 3: 清除浏览器缓存

按 `Ctrl/Cmd + Shift + R` 硬刷新页面。

### 步骤 4: 验证翻译

刷新论坛页面,检查之前显示为键名的地方是否已显示中文。

### 步骤 5: 如果仍未解决,检查语言包状态

```bash
# 查看已启用的扩展
heroku run "php flarum info"

# 查看应用日志
heroku logs --tail
```

## 🔍 高级排查

### 检查数据库中的语言设置

```bash
# 连接到 JawsDB 数据库
heroku config:get JAWSDB_URL

# 使用输出的 URL 连接数据库,执行:
SELECT * FROM settings WHERE `key` = 'default_locale';

# 应该返回: zh (简体中文)
# 如果不是,更新它:
UPDATE settings SET value = 'zh' WHERE `key` = 'default_locale';
```

### 检查翻译文件是否被正确加载

访问你的论坛,打开浏览器开发者工具(F12):

1. 进入 **Network(网络)** 标签
2. 过滤 **JS** 文件
3. 查找类似 `locale-zh-*.js` 的文件
4. 如果没有找到,说明语言包资源未正确发布

### 检查 storage 目录权限

```bash
# 在 Heroku 上检查权限(注意: Heroku 文件系统是临时的)
heroku run "ls -la storage/"

# 应该看到以下目录可写:
# drwxr-xr-x cache
# drwxr-xr-x locale
# drwxr-xr-x views
```

## 📝 预防措施

为避免将来出现类似问题:

### 1. 自动化缓存清除

在 [`composer.json`](../composer.json) 中已配置:

```json
"scripts": {
    "post-install-cmd": [
        "@php flarum assets:publish || true",
        "@php flarum cache:clear || true"
    ],
    "post-update-cmd": [
        "@php flarum assets:publish || true",
        "@php flarum cache:clear || true"
    ]
}
```

每次部署时会自动清除缓存。

### 2. 部署后手动验证

每次推送新代码到 Heroku 后:

```bash
# 监控部署日志
heroku logs --tail

# 等待看到类似输出:
# "Publishing assets..."
# "Clearing cache..."
```

### 3. 使用 Heroku 计划任务

如果需要定期清除缓存,可以使用 Heroku Scheduler:

```bash
# 安装 scheduler 插件
heroku addons:create scheduler:standard

# 添加每日缓存清除任务
heroku addons:open scheduler
# 在 Web 界面添加: php flarum cache:clear
```
